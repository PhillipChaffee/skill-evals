# Changelog

## Unreleased

- Rules, hooks and preconditions. The config keys `rules` (a directory of the subject) and `instructionFile` (a file of the subject) name a subject's rules; both follow the subject's containment and link rules (a path that leaves the subject, a link, or a missing path is a usage error), and the `none` subject has none. An adapter with the capability `rules` implements `Harness.installRules(files, input)`, which installs them the way its harness reads them and returns what it installed; the record keeps `RunRecord.rules` as `{ installed, reportedLoaded }` (`reportedLoaded` is null when the harness reports no rule), and a rule that would land on a file of a case's `workspace/`, shared fixtures or `home/` is a usage error that names both. Claude Code declares `rules`, installing the rules directory as `<config dir>/rules` and the instruction file as `<config dir>/CLAUDE.md` in the run's home (read from the CLI binary's strings, not from a run); its stream reports no loaded rule. Transcript events of type `hook` carry `{ event, command, exit, contextBytes, context }` (context cut at 4,000 characters, with the cut stated); Claude Code declares `hooks`, passes `--include-hook-events`, and reads `hook_response` events (the stream's schema read from the binary), and hook events are never tool calls. New checks `hook_fired` (`event`, `min` default 1, `max`) and `context_injected` (`pattern`, `flags`, `source` of `hooks`, `rules` or `any`; it reads hook contexts and the rule and instruction text that the harness reports, never the files the run installed). New case key `preconditions`, a list of checks of the types that are marked `precondition` (`context_injected`, `hook_fired`, `skill_available`, `skill_loaded`; any other type is a load error): they are scored first, one that scores 0 makes the run invalid with `precondition not met: <check>`, the judged, decision and command checks of that run are not run, and a precondition never counts in the score or the case's `checks`. What a precondition needs makes the case not applicable. `--include-hook-events` is new in the Claude Code invocation. Migration: none; a case and a record without these keys read as before.
- Seeded history and prior-session stores. A case may have a `history.json` (a non-empty list of `{ role, text, toolCalls? }`, each call `{ name, input, output? }`; an unknown key is an error, even under `--lenient`) and a `sessions/sessions.json` (a list of `{ id, startedAt, cwd?, messages }`); both follow the case-directory containment and link rules and count in `inputHash` and `caseHash`, and a case without them keeps both hashes it had. The history reaches the agent in one of two modes, recorded as `RunRecord.historyMode` (`native`, `preamble`, or null for a case with no history): `preamble` puts a block headed `Earlier in this conversation (<n> messages):` in front of turn 1, fenced with more backticks than any run in the history, and works on every adapter (all declare `history`); `native` writes the history into the harness's own session store and resumes it, and is the mode of an adapter that declares `historyNative`. The default is `preamble` for every adapter; `--history-mode native|preamble` (config key `historyMode`, kept in `meta.historyMode` and in the run key of a case with a history) forces one, and forcing `native` on an adapter without `historyNative` makes a case with a history not applicable with its reason, not a usage error. A case needs `history` (`historyNative` under `native`), `sessionStore` for `sessions/`, and is not applicable under `preamble` when it says `"requires": ["historyNative"]` or when its first turn is an `invoke`. The history is in `<run>.history.json`, not in the transcript: the transcript file and `SKILL_EVALS_TRANSCRIPT` hold the agent's events only, a `command` check gets the history as `SKILL_EVALS_HISTORY`, no check and no judge reads it, and `show` prints it as `h0`, `h1`, …. A sessions `cwd` is relative to the workspace; an absolute path or one that leaves it is a load error; `CLAUDE_CODE_PROJECT_DIR_NAME` is never passed to a harness; a prompt that starts with `/` is not applicable under `preamble`. Files are planted after the setup steps and the login files and before the harness, so they are part of the home seed and not the agent's changes. `Harness.historyMode`, `installHistory` and `installSessions` are new, and Claude Code has the code that writes `~/.claude/projects/<encoded cwd>/<id>.jsonl` (read from the binary's strings, `docs/design/multi-turn-and-history.md`) but declares neither `historyNative` nor `sessionStore` until Task 29 confirms with a real model that it accepts a planted session. New example cases `examples/cases/history` and `examples/cases/sessions`, and the target case `catch-up-from-history`.
- Asking the user, and conditional replies. The tool kind `question` is new: Claude Code's `AskUserQuestion` maps to it, and the adapter declares the new capability `askUser` (no other adapter does until Task 29 confirms its question tool); `Parsed.askedUser` is read from the result's `permission_denials`, unconfirmed against a real run. A final message that ends with a question mark never counts as asking. The new check `asked_user` takes `min` (default 1), `max`, `pattern` (a regular expression for the question text) and `by`; `ended_awaiting_user` passes when the last event of the main agent is a question call, or the adapter says the run stopped for input, in a turn or at case level. A turn may be `{ "reply": { "whenAsked": "<regex>", "prompt": "<file>" } }`: it is sent only when the previous sent turn ended awaiting the user and a question matches, and is otherwise recorded as skipped `"not asked"`; its checks are not scored, are left out of the run score and do not make the run invalid, and the report says `not scored: turn N was not asked`. A reply needs `multiTurn` and `askUser` and may not be the first turn. The record's top-level `loaded` is now the union over every turn's process, not the first's. The new examples are `examples/cases/asked_user` and `examples/cases/ended_awaiting_user`. `AskUserQuestion` calls were kind `other`; they are now `question`, and kind `other` no longer matches them, so a `tool_called`, `first_tool` or `tool_order` that named `other` sees them differently (and `{ kind: "other", max: 0 }` no longer counts them). A run whose only checks are on a reply turn that was not asked is invalid (`nothing was scored: ...`); `diff` leaves a check that was never scored out of its means; a `clear` ends the session a reply could answer; a reply is matched against the questions of the message the turn ended on, not earlier ones; `Parsed.askedUser` is set only when the harness refused the very question the run ended on; `validate` warns about a reply turn with no `asked_user` or `ended_awaiting_user` check before it; `rescore` and `rejudge` do not re-score `asked_user` and `ended_awaiting_user` for a record made before the question kind (they list them as `not re-scored: recorded before the question kind`, with one warning), and every new record carries `askedUser`.
- Multi-turn cases, per-turn checks and user invocation. A case may list `turns` in place of `prompt.md` (both is a load error): each turn is `{ "prompt": "<file>" }`, `{ "invoke": { "skill", "args" } }` or `{ "event": "compact" | "clear" | "resume" }` with optional `checks`; the first turn may not be an event, a prompt file stays inside the case and outside `grader/`, and a variant may give its own `turns` (a variant now gives exactly one of `prompt`, `promptAppend` and `turns`). One harness process runs each turn, in one workspace and home, and continues the session of the turn before (`RunInput.session` is the previous turn's `Parsed.sessionId`; `RunInput.turn` says which turn it is; a turn that states no session id ends the run as invalid with `turn N gave no session id to continue`). `timeoutSeconds` and `maxTurns` apply to each turn; the whole run has `totalTimeoutSeconds`, default `timeoutSeconds` times the turns; a turn stopped by `maxTurns` or a time limit ends the run, the turns after it are recorded as skipped (`stopped`) and not sent, and `stoppedBy` is that turn's. The merged result sums tokens, cost (null unless every turn stated one) and duration, gives every event its `userTurn` from 1, renumbers calls across turns, and writes one transcript file. The record gains `userTurns` and `turnChanges` (a hash snapshot of the workspace after each turn, no copies), and a check result gains `turn`, which the report shows as `turn N`. A turn's checks see that turn's transcript, calls and final text; `file_changed`, `file_unchanged` and `files_changed_only` use that turn's changes; every other file check and `command` check sees the final workspace; a turn's checks may not be `judge`, `decision` or on `root: "home"`, and a check of a turn that was not sent scores 0 with the reason. Needs: more than one turn needs `multiTurn`, `invoke` needs `userInvoke`, an event needs its own capability; a case that needs more than the harness declares is not applicable. `Harness.userInvocation` maps an invoke to the harness's user syntax. Claude Code now declares `multiTurn` (`--resume`), `resume` and `clear`, confirmed from `claude --help` 2.1.330; it does not declare `userInvoke` until a real model has shown that `/<skill> <args>` loads the skill in `-p` (see `docs/design/multi-turn-and-history.md`); no adapter declares `compact`, and `pi`, `opencode`, `codex` and `cursor` declare none of these, because their CLIs could not be read here. A `compact_boundary` event in Claude Code's stream is a `lifecycle` transcript event. `placeSkills` keeps a copy that is already in place, so a later turn does not undo what the agent changed in it. The case key `totalTimeoutSeconds` is new, and the example is `examples/cases/turns`; the guide is Multi-turn cases. Changed on purpose: two messages (`a variant needs exactly one of "prompt", "promptAppend" and "turns"`, `no prompt source; add a prompt.md, or list "turns"`), the schema, the capability table of `applicability.test.ts`, and the example check of `src/docs/examples.test.ts` (a case with `turns` has no `prompt.md`). The input hash, the case hash and the run key of a single-prompt case are unchanged, and a test pins the last two to their values before turns. Fix round 1: every harness process of a run is held to the report of what it loaded (`unexpected` and `reportMissing` are the union, `subjectLoaded` must hold for each process that reports, and `TurnRecord` keeps each `loaded` and `sessionId`); a process that is resumed with one session id and reports another invalidates the run (`turn N continued session X but reported Y`); a reason in a turn names a call by its number in the whole run, as `show` does (the `sameTurn` reason now says "assistant turn"); a variant of a case with `turns` must give `turns`; a case whose checks are all in its turns may leave `checks` out; `clear` and `resume` turns take no checks; the last turn gets exactly the remaining part of `totalTimeoutSeconds`; a turn that was not sent names the cause; the final text is the last message or invocation's, not a trailing compaction's; `user-only-skill` runs on a test-only harness that declares `userInvoke`. Changed on purpose: the wording of the `sameTurn` reason in `tool-order.test.ts` and `target-agent-cases.test.ts`, and `case.schema.json` makes `checks` optional when `turns` or `variants` is present. New target cases: `pressure-across-turns`, `user-only-skill` and `user-only-skill-natural`.
- New commands `init`, `explain` and `show`, and the examples, schemas and docs ship in the package. `init <id> --kind trigger|negative|behaviour|pressure|agent|outcome|prose` (flags `--kind`, `--cases`) writes `prompt.md` and `case.json` from a template under `--cases` (default `evals/cases`); the id follows the rules of case ids (no `@` or `,`, no part that starts with `_`, not inside another case), an existing directory is refused with exit 2, and every template passes `validate`. `explain <id>` prints a case as JSON in Markdown with its variants, the layers of files in order, the setup steps, every check with its defaults written out, the capabilities it needs, and whether each installed harness can run it, from a lookup on `PATH` only (no harness is started); an unknown id exits 2 and lists the cases. `show <out dir> <case> [--subject <label>] [--rep <n>]` prints one line for each transcript event (agent, kind, name, and input or output cut at 200 characters, said where it cuts), numbers calls as the checks do (`call #0`), then each check with its score and reason; a missing transcript is a line saying so, an unknown case, subject or rep exits 2 and lists what exists, and it takes no lock. New flags `--kind` and `--rep`. `examples/graders/text-metrics.mjs` is a documented `command` grader: `--max-sentence-words`, `--percentile`, `--banned <file>`, `--strip-code`, exit 0 `ok`, 1 a violation on each line, 2 a usage error (see the new prose-checks guide). The package `files` now include `examples`, `schema`, `docs/design` and `docs/src/content/docs`. Changed on purpose: the `unshipped` pattern of `src/package.test.ts` now allows `.ts` files under `examples/`, which are the material of cases, and the test asserts that the tarball holds `examples/cases/hello/case.json`, `schema/case.schema.json` and `docs/src/content/docs/reference/checks.md`. There is now one example directory for each check type under `examples/cases/<check type>/`, and `src/docs/examples.test.ts` fails until a new check type has one; to make that so, `examples/cases/agent-dispatched`, `first-tool`, `skill-available`, `skill-file-read`, `subject-unchanged`, `tool-order`, `tool-output-matches` and `transcript-matches` are renamed with underscores (`agent_dispatched` and so on), and the entries of this file that name the old paths refer to those. Fix round 1: default values are now one table. `FieldDef` gains `default` (by check type, with `*` for any), the rules, `explain` and the Fields table of the checks reference read it, and `src/check-defaults.ts` is gone; `withDefaults` now also fills `ifUnsupported`, `via`, `created`, `sameTurn`, `first`, `strict`, `which` inside `before` and `after`, `scale`, `votes` and `sees`, and `tool_not_called` shows its fixed `min: 0, max: 0`. Case ids and `init` share one rule (`src/case-id.ts`): a directory name with a control character (`\x00` to `\x1f`, `\x7f`) or over 255 bytes is a load error, and `init` accepts any name that discovery accepts except an empty part, `.`, `..` and a leading `_`; every file system failure of `init` is exit 2, `init` makes the case directory without `recursive`, writes with `wx` and removes what it made when a write fails. `show` cleans every printed string (control characters become `\xNN`), quotes names, kinds and agents, cuts each reason line at 200 characters, prints `?` for an event with no agent, and heads a run `<subject>, rep <n>`. `text-metrics.mjs` reports an empty text as `no text` (exit 1) unless `--allow-empty`, takes the exact integer percentile rank, ends a sentence after a closing `)`, `"`, `'`, `*`, `_` or `]`, closes a fence with a longer one, normalizes to NFC and treats combining marks as word characters, and exits 2 on any unexpected error. The eight `examples/cases/file-state/*` directories are now the top-level `dir_exists`, `file_absent`, `file_changed`, `file_count`, `file_lacks`, `file_lines`, `file_unchanged` and `files_changed_only`.
- New commands `rejudge` and `diff`, and `--keep-workspaces` (config `keepWorkspaces`). `--keep-workspaces` archives each run after its checks, with the system `tar`, as `<run>.workspace.tar` in the output directory: `workspace/`, `seed/`, `remotes/` (when the run has one) and `home/`, plus `home-seed.json`; the harness's login files and the grader's copy are never in it. A missing `tar` is a usage error for this flag only. `RunRecord` gains `workspaceArchive` (`{path, bytes}` or null) and `inputHash`, the sha256 of what the agent saw (prompt, `workspace/`, fixtures, setup steps, `home/`, harness, model, `maxTurns` and env names; not the checks, `grader/` or rubrics), written on every new record. `rejudge <out dir>` (flags `--cases`, `--case`, `--judge-model`, `--judge-api`, `--judge-harness`, `--out`) scores stored runs again against the cases as they are now: it rebuilds each outcome from the transcript file and the unpacked archive, re-runs every check, sends judge calls through the directory's judge cache, never starts the agent's harness, and leaves `results.json` and `results.jsonl` untouched (it writes `results.rejudged.json`, or the full set into `--out`, which may not be the source). A run whose `inputHash` differs from the case's is not re-scored ("the case changed beyond its checks"); a run without an archive keeps the old score of each check that needs files, and a new such check has no score; a case missing from the cases directory keeps its records; a run stored with `skippedGraders` is finished. `diff <a> <b> [--strict]` compares two results: the score change per case with run counts, newly failing and newly passing checks (mean score over valid runs of at least 0.5, matched by description, then by position for duplicates), and cost and duration; a warning block comes first when models, harnesses, tool version or any case hash differ or a side has no meta, and `--strict` turns a warning into exit 2. Commands may now take positional arguments; a command that takes none still refuses one. Staging for the archive happens before the checks run; a login file is left out by path and by content, and no removal follows a link (`removeLogin` no longer follows a symlinked parent either). `meta` gains `lenient` and `judge` (`via`, `harness`, `model`), and `rejudge` defaults to them (and accepts `--lenient`); decision answers are cached by slot like judge answers; `rejudge` refuses an `--out` that holds results, locks it, and checks the source before locking it; `diff` covers every subject label both results have. A login file is matched by content only from 32 bytes, and `workspaceArchive.omitted` lists the files left out by content; `rejudge` loads cases with the recorded `lenient`, uses one decision model for the cache key and the request, refuses `--out` inside the source, and locks the source before it creates `--out`. The commands page names each command with its arguments. An unscored check that is not a `command` check now reads `a file check has no score` in the invalid reason. New guide: Re-judge stored runs and diff two results.
- A comparison now says how sure it is. Every case and the suite get a verdict, `helped`, `hurt` or `within noise`, with the delta and its 95% percentile bootstrap interval (`helped (+0.12, 95% −0.03..+0.27)`): 2000 resamples of the valid run scores, a seeded mulberry32 generator (`--seed`, config `seed`, default 1, a positive integer up to 4294967295, recorded in `results.json`), the suite delta stratified within each case, and one footnote that states the method. A case with no valid run on a side has `n/a` and no verdict. New command `calibrate` runs the subject against itself (5 reps by default, one harness) and writes `noise.json` (`schemaVersion`, `perCase` `sd` and `maxAbsDelta`, `perCheckType` `sd`, `suite` `sd` and `p95AbsDelta`) beside the usual files; `noise.json` also records `harness`, `reps`, `seed` and `caseIds`, and `perCase` has `p95AbsDelta`; `run --noise <file>` (config `noise`) reads it strictly (an older file without those keys is refused), applies it only to its own harness, and a delta no larger than its case's `p95AbsDelta`, or the suite's, reads `within noise`; a case the file lacks is judged by its interval, and the report notes a file from another harness, at other reps, or of no matching case. A case with fewer than 5 valid runs on a side (`MIN_RUNS_FOR_VERDICT`) reads `too few runs (A n=3, B n=3)`, and the suite needs the same in every case; bars do not change. `calibrate` applies no pass bar. A config `minDelta` is ignored under `score` with the same note as a case's. `--min-delta <x>` (config `minDelta`, -1 to 1; write a negative value as `--min-delta=-0.1`) and a case's `minDelta` are bars on the point delta B minus A: a missed bar joins `belowBar` and the exit is 1, and a verdict alone never changes the exit code. They apply to `run`: `--min-delta` with `score` is a usage error, and a `minDelta` in a case or the config under `score` gets the note `minDelta applies to run`. When A or B is `none`, each non-guard case gets the first label that fits, `non-discriminating` (the none arm scores at least `NON_DISCRIMINATING_FLOOR`, 0.9), `failing with the subject` (the subject scores below `FAILING_CEILING`, 0.5), `discriminating` (the verdict is `helped`), else `no evidence`. The case table gains a flake column, the share of valid reps that disagree with the majority outcome of each check for each subject (a rep passes at a check score of 0.5). The markdown and HTML reports show the verdict, flake and discrimination, `report.json` cases gain `delta`, `low`, `high`, `verdict` and `discrimination` and the report a `method` object, and JUnit changes only through the bars. `results.json` gains `seed`, `noiseFile`, `minDelta` and `comparison`. The common-set line notes how many of its cases ran with checks skipped on some harness. Changed on purpose: the markdown case table has two more columns for a comparison (Verdict, Flake) and one more for `score` (Flake); an unknown flag that another command takes now says which. Guides: Set a pass bar, Read the report.
- Numeric flags (`--reps`, `--jobs`, `--retries`, `--max-cost`, `--max-duration`, `--min-score`, `--decision-timeout`) now read a decimal literal only, with surrounding whitespace trimmed as before. Empty or blank text, hexadecimal (`0x1`), binary (`0b1`), octal (`0o7`), `Infinity` and digit separators (`1_0`) are rejected with `--flag is not a decimal number`; 0.0.1 read `--reps ""` as 0 and `--reps 0x1` as 1.
- A command can be stopped by a budget, an interrupt, or a failure of the infrastructure, and say so. `--max-cost <usd>` (config key `maxCost`) and `--max-duration <min>` (`maxDuration`) stop new runs once this command's summed cost or wall time is reached; runs in flight finish with their judged and decision checks skipped (`skipped: budget reached`, `skippedGraders: true` on the invalid record), `results.json` has `partial: { reason: "budget" | "duration" }`, and the exit code is 4, which wins over 1. `--max-cost` is a usage error when a selected harness, the judge or a decision check reports no cost (adapters declare `reportsCost`). SIGINT and SIGTERM kill the harnesses, write `partial: { reason: "interrupted" }`, release the lock and exit 130. `--retries <n>` (`retries`, default 0) makes a run again after a harness crash, a rate limit (adapter `isRateLimit`, unverified against real harnesses; waits 30 s times the attempt) or a timeout before any agent event (the opening `init` event does not count); the record's `attempts` lists the error, cost and duration of each earlier attempt. The progress line ends with `[n/N] $<spent> ETA <time>`, and `results.json` has `notRun`, the runs that did not run, with a "Stopped early" section in the report. See `guides/ci`.
- Runs can go in parallel, results are written as runs end, and a stopped command can continue. `--jobs <n>` (config key `jobs`, default 1, a positive integer; `run` and `score`) keeps `n` runs in flight, each with its own home, workspace and subject copy; `results.json` lists the records in plan order (each harness, case, rep, subject) whatever order they end in, and the progress lines print in the order they end. The output directory gains `results.jsonl`, one line for each finished run (the run record plus `key` and `attempt`, the number of the attempt that made the record), added with one `appendFileSync` call, and `results.json` is rewritten after every run through `results.json.tmp` and a rename, so it is always whole. `--resume <dir>` implies `--out <dir>` (a different `--out`, or a directory with no `results.jsonl`, is a usage error): a run whose key has a valid record in `results.jsonl` is not repeated and is marked `(reused)`; the others run and are added, and the judge cache is on. A key is the sha256 of the canonical JSON of the case hash (the resolved case and every file of its directory, its shared fixtures and its grader), the subject revision (the content hash of the run's export, exclusions applied, for a directory and a ref; `none`), the harness and its executable (real path, size, mtime), the model, the rep, the tool version, the names and value hashes of the passed `env`, and the scoring (judge harness, API, URL, fallbacks and model, decision model and URL, `--isolated`, `--lenient`). A record is reused only when it is the last `results.jsonl` line of its harness, case, subject label and rep; the judge cache is kept for each run on resume; `--resume` without `--model` warns; `<out>/.lock` (`{pid, hostname, bootId, startTime}`) stops two commands on one directory and tells a live holder from a leftover; the judge harness's executable is part of the key when it is not the harness under test; a run that throws leaves `results.json` with `partial: { reason: "error" }`; `results.json` is written at the start and at most every 10 seconds, with `partial: { reason: "running" }` until the last write (`Results.partial`, null when final). A last line of `results.jsonl` that is not valid JSON is dropped with one warning and its run repeats; an earlier bad line is a usage error. New command `plan` and the switch `--dry-run` on `run` and `score` print the matrix of harnesses, cases, subjects and reps, the run count and the not-applicable cases, start no harness and write nothing; with `--resume` or `--out` naming a directory of an earlier command they also estimate cost and duration from per-(harness, case) medians (`estimate covers K of N runs`). `Case` gained the optional `dir`, `Subject` the `revision`, and `onRun` a second argument `{ reused, progress }`. A fresh command into an `--out` whose `results.jsonl` has a line is a usage error (`pass --resume`, remove it, or choose another `--out`). A `plan` also raises the usage errors of the command and, with a prior directory, says how many runs a resume would reuse. A link in `grader/` that leaves it is a load error. New guide: Run in parallel, resume and plan.
- Turn limits are enforced by the runner, and `stoppedBy` says who ended a run. `exec` takes `onStdout`, which sees each chunk of standard output and may answer `"stop"`: the whole process group is killed as on a timeout, and the result is `stopped: true` with no failure. An adapter with `turnGrouping` (Claude Code, OpenCode, Pi) gets the optional `Harness.countTurns(line, state)`; the session joins chunks into whole lines, counts main-thread turns (a subagent's never count), and stops the run as turn `maxTurns + 1` begins, so a partial extra turn may show in the transcript and nothing seen is cut. A run stopped at `maxTurns` is valid and scored, its final text is the last main-thread assistant text, and Claude Code's own `error_max_turns` result is now the same stop and no longer a failed run. Run records gain `stoppedBy` (`agent`, `maxTurns` or `timeout`; `agent` for a crash too), `maxTurnsEnforced` (null with no `maxTurns`, false on a harness that cannot count turns), `turns` and `firstOutputMs` (all four absent from earlier records); the report lists a harness that cannot count turns under "Limits not enforced". New case key `onTimeout` (`"invalid"`, the default, or `"score"`): with `score`, a timed-out run is scored on what it left, with no error. Only a stream with no ending (`Parsed.unfinished`) is excused on a stopped run; a harness-reported error (Claude Code's error result, Pi's error turn, OpenCode's error event), an adapter that cannot read the stream, a failing turn counter (`the turn counter failed: ...`) and the other checks (`subjectLoaded`, `--isolated`) still invalidate it, and an error result's text is never taken as the final text. A stop request counts only while the process is live and its time has not run out. With `onTimeout: "score"`, a timed-out run that wrote nothing is invalid (`timed out after N s before the agent did anything`). A timed-out run now reports `timed out after N s` as its error when the harness reported no error of its own, so a timeout with a cut stream no longer reads `no result event`; when the harness did report an error, that error is kept, as before. A judge session that the runner stopped at `maxTurns` (`the judge was stopped at maxTurns`) is a failed judge attempt: retried as any failed judge session, and never cached; a judge that times out fails with its timeout error, as before. A stop is recorded (`stoppedBy: "maxTurns"`) only when the runner's kill ended the process; a process that exited by itself with a code, or after its time was up, is not a stop, and Claude Code's `error_max_turns` excuses only exit code 1 with no signal. The report gains "Stopped by the runner" (`K of M runs stopped at maxTurns`, `K of M runs timed out and were scored (onTimeout: score)`) and the progress line says `(stopped at maxTurns)` or `(timed out, scored)`. OpenCode counts only its main session (the first `sessionID`). `Parsed` gained the optional `hitMaxTurns`, `Harness` the optional `countTurns`, and `Case` the optional `onTimeout`.
- The judge and `decision` checks can see what the agent did: `sees` (`final`, `transcript`, `files`; default `["final"]`, which sends the 0.0.1 prompt byte for byte), `files` (globs of the workspace, each file cut to 20,000 characters, a binary file or an image named and not shown) and `maxChars` (default 60,000, for the transcript rendering `renderTranscript`, which cuts each tool output to 400 characters and then drops the oldest, and says what it left out). Exit codes (`EXIT`, exported with `exitCodeOf`, one function for the command line, `summary.json` and `evaluate`'s new `exit`): 0 ok, 1 a bar missed, 2 usage, 3 invalid runs above `--max-invalid`, 4 stopped by `--max-cost` or `--max-duration`, 5 an internal failure, 130 interrupted; when several apply the first of usage, interrupted, error, partial, invalid, bar wins. Changed on purpose: a run that is invalid now exits 3, where 0.0.1 exited 1; a subject directory that changed while the command ran now exits 3 (it kept its message), where it exited 1; an internal error that is not a usage error now exits 5 with its stack trace on standard error, where the process died with an unhandled rejection; `validate` still exits 2 on a problem and `check` still exits 1 when a harness fails. `--max-invalid <fraction>` (config key `maxInvalid`, 0 to 1, default 0) exits 3 only when invalid runs divided by the planned runs of the applicable cases exceeds it; a run that did not run because a limit stopped the command is not invalid. Changed on purpose: every score in the report now carries its run count: the suite line reads `Suite score: 0.80 (2 of 3 cases, 5 of 6 runs)` (it read `(2 of 3 cases)`), a case score reads `0.80 (3 of 3 runs)`, two subjects read `(A 3 of 3 runs, B 2 of 3 runs)`, a judged or decision check's rate and the common-set and pass-bar lines carry the count too. `--report md|json|junit|html` (a list; config key `report`; default `md`): `md` goes to standard output only when listed, the others to `report.json`, `report.xml` (JUnit: one testsuite for each harness and subject, one testcase for each case; below the bar is a `failure`, an invalid run an `error`, a case that is not applicable or did not run `skipped`) and `report.html` (one file, inline style, tables only, no script, no external reference, every value escaped) in the output directory. `summary.json` is written with every final write of a command (normal, stopped, interrupted, failed), never on the interim writes and never on a usage error: `{ schemaVersion, exit, suites: [{ harness, label, score, applicable, total, validRuns, plannedRuns }], belowBar, invalid, notApplicable, partial, costUsd, durationMs }`; `report.json` is `{ schemaVersion, summary, cases }`. `results.json` gains `schemaVersion: 1` and `meta` (`toolVersion`, `harnessVersions` from `<bin> --version` read once for each harness and null on failure, `models`, `subjects` with `revision` and `dirty`, which is null outside git, `caseHashes` by harness and case id, the hash that the run key uses, `isolated`); `results.json` also gains `minScore` and `maxInvalid`; `SuiteScore` and `CaseScore` gain `runs`, `CommonSet` gains `runs`. Harness versions are read in parallel, only for harnesses that run a case and for the judge harness when a judged check is selected; the command waits for them, and a harness that takes over 10 seconds has its process group killed and reads `null`. `plan` and `--dry-run` read no version. A case with no valid run makes the command exit 3 whatever `--max-invalid` says, so a suite that scored nothing is never a pass. In JUnit each testsuite has a `suite score` testcase (a `failure` under `--min-score`) and, for a changed subject, a `subject unchanged` error; a case whose invalid runs are within the budget is filed by its score, and `report.json` marks it `tolerated`. The reports are written before `summary.json`, each written file is named on standard error, a command removes the `summary.json` and `report.*` of an earlier one when it starts, a failure before the first run leaves a summary with exit 5, and an exception or rejection that nothing caught exits 5. `evaluate` gains `onFinal`. `src/report.ts` moved to `src/report/markdown.ts`. ## 0.0.1

The first release. The runner comes from the `evals/` folder of [magic](https://github.com/PhillipChaffee/magic), where it scored that one set of skills.

- Run it in any project. The project is the git repository that holds the working directory, and the cases default to `evals/cases` in it.
- Score a plugin, a plain folder of skills, or `none`, which loads no skills and is the baseline for a comparison.
- Set defaults in an optional `skill-evals.config.json`.
- Use it from code with `evaluate`, `loadCases`, and `HARNESSES`.
- A prompt that starts with a dash reaches the agent in every harness.
- Windows is not supported.
- The package is written in TypeScript. It ships compiled JavaScript and type declarations, and still has no dependencies.

- A `decision` check asks a decision model a question about the final answer. The case sets what each allowed answer is worth, the model returns a probability for each answer, and the check's score is the expected value. All decision checks of a case go out in one request for each run.
- `--decision-model` and `--decision-url`, and `decisionModel` and `decisionUrl` in the config file, set the model and its endpoint. The client speaks Baseten's System One API and reads its key from `BASETEN_API_KEY`. It was written from the API's documentation. It has scored checks against bison-1 on a self-hosted deployment, and has not yet called Baseten's hosted API.
- `--decision-timeout <seconds>` and `decisionTimeout` in the config file set how long one request to the decision model may take. The default stays 60 seconds. A cold start of a self-hosted model can take that long.
- A decision reply whose probabilities were rounded to 6 decimals is accepted. The sum over the allowed answers may differ from 1 by 0.0000005 for each answer, where the limit was 0.000001 in total, which rejected three honest options that added up to 0.999999.
